# はまりやすい点

## 作品を書くときに気をつけること

- **折れたパネルの近くに置いた物が、パネルと前後が入れ替わったり突き抜けたりする。** 左右とも背から 200 以上張り出すパネルは背で「くの字」に折れる。一番奥のパネルは端ほど手前に出て、それより手前のパネルは逆向きで端ほど奥へ引く(どちらも X の位置で `|X| × tan(12°)`、ページ端で約 150)。近くに置く物はその分を見込んで Y を決める。エンジンが警告を出す。
- **背を少しだけまたいだパーツが、めくるとき左右に分断される。** 机や柵の端が背を数十だけ越えた、という置き方で起きる(左右とも 200 以上張り出すパネルは自動で折れるので起きない)。片ページに収まるよう X か幅を直すか、`fold` でくの字に折る。エンジンが警告を出す(直す X の値つき)。
- **背を越えて動くパーツを、出発側のページに付けたままにしない。** 反対側のページの上まで来たパーツが出発側に付いたままだと、そのページがめくられるときにパーツを突き抜ける。エンジンが、根元がいまある側のページへ毎フレーム付け替えている(`dx` のあるパーツだけ)。
- **背をまたぐパーツを動かすと絵が切れる。** 幅が X=0 をまたぐパーツは左右のページに切り分けられる。`dx` などで動かす物、`yaw` を付ける物には `nosplit: true`(必要なら `side`)を付ける。エンジンが警告を出す。
- **動きに現在時刻を使わない。** `Date.now()`、`performance.now()`、`requestAnimationFrame`、`Math.random()` を作品側で使うと、巻き戻しや静止画チェックで絵が再現しない。時間は `tl`、乱数は `rnd(seed)`。
- **登場前の物は `op: 0` にする。** `sc: 0` だけだと影や光が残ることがある。
- **夜を `grade` だけで作らない。** 全体が濁って「暗い昼」になる。パーツと地面も夜の色で描く。
- **高い物はカメラの外に出やすい。** 高さ 500 を超える物は `tilt` と `d` を上げ、`--spread N` で先端まで映っているか見る。字幕は画面下 130px を使うので、本の手前側がそこに被りすぎないようにする。
- **高さ 1000 を超える1枚板は、カメラが近いと下のほうが描かれないことがある。** 巨木や塔を1枚で置くと、カメラを引いたコマでは正しく出るのに、寄ったコマ(`d` 250〜520、既定の `tilt`)では上のほうだけが浮いて見える。原因は特定できていない。板を上下2枚に分け、上の板を `lift` で浮かせると出なくなる(書き方は `themes/default_storybook/gimmicks.md` の「下から伸びる」)。高い物のある見開きは、引いたコマだけでなく寄ったコマも撮って確かめる。
- **`yaw` で回して `lift` で浮かせた板に、`dyn` の `clip` を使わない。** 板の下のほうが欠けて、上のほうだけが浮いて見える(`yaw: 0` の板では起きない。原因は特定できていない)。十字や X 字に組んだ高い物を下から伸ばすときに当たる。絵の中に切り抜き(`clipPath`)を入れ、その四角を `anim` で動かして伸ばす(書き方は `themes/default_storybook/gimmicks.md` の「下から伸びる」)。
- **スクリプトで撮るときは、Chrome を `--enable-gpu` 付きで起動する。** 付けないとヘッドレスの Chrome は画面の合成をソフトウェアで行い、立っている板の箱の上へはみ出した絵(煙、光の粒、動かした眉や旗など)が箱の上端で切れて写る。普通に開いたブラウザでは切れないので、動画や検査の画像だけが実物と違ってしまう。`scripts/` の `check.mjs` `render-video.mjs` `gallery.mjs` `parts-sheet.mjs` は付けてある。自分でブラウザを起動して撮るときも付ける。
- **主役の前に主役を置かない。** 窓・看板・小さい人物など見せたい物の手前(Y が大きい側)に大きなパーツを置くと隠れる。横にずらす。
- **字幕は2行とも最初から出る。** 見せ場のせりふを先に見せたくないときは、その行を `[tl, '文']` にして時刻を指定する。
- **手前に大きな物を置くと主役が隠れる。** いちばん手前(Y>780)は高さ 120 以下の草や茂みにとどめる。
- **人物が小さすぎる。** 建物との実寸比に合わせると顔がつぶれる。人物は大きめに。
- **anim で動かす絵は小さく保つ。** anim は毎フレーム絵を描き直すので、1400px 幅の背景に anim を付けると重くなる。動く部分は別パーツに分ける。
- **1見開きのパーツは 45 個程度まで。** それ以上は実機での滑らかさが落ちやすい。紙ふぶきのような粒は 15 個前後で足りる。
- **`w0,h0` と絵の実寸をそろえる。** 箱より絵がずっと小さいと、根元の位置と影がずれる。

## エンジンが内部で避けていること(機構を直したくなったら読む)

- **同じ平面に重なる板は、片方が描かれないことがある**(Chrome の3D並べ替え)。このため、背をまたぐパーツは「左右それぞれ、自分のページ分だけの大きさの板」に切り分けている。全幅の板2枚を `clip-path` で半分ずつ見せる方法は、右半分が消える。
- **背をまたぐ板を、左右とも背に垂直な同じ平面に立てない。** ページをめくる途中は左右のページが角度を持つので、同じ平面内で板が回って互いに重なって見える。このため左右の板を背で「くの字」に折り(`fold`)、起き上がり角を開き角から `tanρ = sin(fold)·tan(φ/2)` で決めている。この式なら折り目が常に左右で一致し、とじるとページの間に収まる。向きは、一番奥のパネルが奥へ、それより手前のパネルが手前へたたまれるように決めている(手前のパネルが奥へ倒れると、後ろの物に覆いかぶさる)。
- **切り分けた板の中身は `contain: paint` で「絵の箱」の中に閉じておく。** 箱を板いっぱい(上の余白を含む)に広げると、下の光の筋が戻る(試して確認済み)。その代わり、**背をまたいで切り分けられる板では、絵を `w0×h0` の箱の外へはみ出させられない**(上に突き出た飾りや、板の中で回した絵は切れる)。はみ出す分は箱を大きく取って中に収める(上へのはみ出しは `check.mjs` が警告する)。`contain: paint` で閉じておかないと、GPUで描画する実ブラウザで、板の上の余白に縦の光の筋が立つことがある(見本では、手前の丘の稜線の木の真上に出た)。板がほかの板と平行でないときに出やすく、折れたパネルでは開いているあいだ出続ける。`check.mjs` のヘッドレス撮影では再現しないので、機構を直したら実ブラウザでも見る。`will-change: opacity` で独立レイヤーにしても筋は消えるが、今度はヘッドレス撮影でだけ折れパネルの右半分が描かれなくなる(実ブラウザでは出ないので、検証の絵だけが壊れる)。
- **本の中(ページ・パーツ)では `mix-blend-mode` を使わない。** Firefox では、ページ上の要素に合成モードがあると、立っているパーツが描かれず影だけになる(紙の粒子と表紙のつやに使っていたのが原因だった)。重ねるだけの通常の合成にする。画面全体に掛ける光や色調(本の外の重ね)には使ってよい。`check.mjs` は Chrome でしか撮らないので、機構や CSS を直したら Firefox でも見る(`firefox --headless --window-size=1920,1080 --screenshot out.png "file://…/index.html?t=11"` で1コマ撮れる)。
- **WebKit(Safari、iOS の全ブラウザ、macOS のアプリ内表示)では、画風の SVG フィルタを掛けない。** 立体の中にある絵に SVG フィルタの参照(`filter="url(#paper)"`)があると、WebKit は立ち上がるパーツを描かず、影だけが残る。フィルタの中身や掛け方(属性か CSS か)を変えても直らず、毎フレームの計算で機械全体が重くなる(macOS の WKWebView で確認)。エンジンは WebKit を見分けて参照を付けずに描くので、そこでは画風の縁取りと質感が出ない(色・影・紙の粒子・本の後ろは出る)。URL の `?nofilter` で、ほかのブラウザでも同じ描き方を試せる。`?nofilter=0` は WebKit でもフィルタを付ける(直ったかどうかを確かめる用)。
- **板を、ページの面より下へ潜らせない。ほかの板も突き抜けさせない。** 面どうしが交わると、ブラウザは前後を決めきれない。Chrome では周りのパーツや字幕がちらつき、Safari ではページに穴があいて机が見えたり、表紙が欠けたりする。1px の潜り込みでも起きる。板の面がページと交わると、Safari はページをその交線(見開きの端から端まで)で割るので、束が細い帯になって見え、帯より手前のページがちらつく。パーツのゆれ(`sway`、`rz`)で下の角が沈む分は、エンジンが板を持ち上げて打ち消している。起きやすいのは、板を大きく倒す・回す仕掛け(倒れる木など)。`rzBase` で倒すときは `rzX` で倒れる側の下の角を中心にし、十字に組んだ板(`yaw`)は倒す前に1つの面へとじる(見本 jack の見開き7)。
- **Mac の Muse アプリ(UA に `HatchMac` を含む)は、埋め込み文書(iframe)を描かない。** 聞き取りページの見本プレイヤーは srcdoc / data: / blob: / object のどれでも真っ黒になる(ページ側の埋め込み方式では直せない)。聞き取りページは `HatchMac` を見分けて、見本を表紙ポスター(`previews/poster.jpg`、`gallery.mjs` が作る)と注記に差し替える。iPhone のアプリ内表示では iframe が描けるので、差し替えるのは Mac だけ。
- **文字(`<text>`)の塗りや線に、グラデーションの参照(`fill="url(#gold)"` など)を使ってもよいが、WebKit ではベタ塗りになる。** macOS のアプリ内表示(WKWebView)では、グラデーションで塗った文字だけが描かれない(同じグラデーションで塗った図形や枠線は描かれる)。エンジンは WebKit のとき、同じ絵の中にあるそのグラデーションのまん中の色に置き換える(`flatText`)。グラデーションの定義は、文字と同じ絵(同じ文字列)の中に書く。別の絵にあると置き換えられず、文字が消えたままになる。
- **WebKit では、舞台を `transform` の `scale` で縮めず、`zoom` で縮める。** 舞台は 1920×1080 で作り、画面に合わせて縮めて見せる。WebKit は `scale` で縮めても、層を「元の大きさ × 画面の解像度」で持つので、iPhone(解像度3倍)では層の合計が 1GB を大きく超え、ページが落ちて読み込み直しになる(Safari の「問題が起きたため…」)。`zoom` なら層そのものが小さくなる。操作系(`player.js`)が WebKit を見分けて切り替え、`?zoom` `?zoom=0` で試せる。`?lite` は、飾りの層(ほこり・ぼけ・影のぼかし・光の合成・紙の粒子)を省いた描き方で、重い機械での切り分けに使う。iPhone で落ちなくなるかどうかは、実機ではまだ確かめていない。
- **机の面は、CSS の背景のまま 3D に置かず、1回だけ canvas に描いた絵にする。** 机は 6000×4600 の板を奥へ倒して置いている。平らなページなら画面に入る部分しか描かれないが、遠近を付けて倒すと遠い部分まで画面に入り、Chrome は1枚の層を1つの細かさで描くので、板のほぼ全面を手前の拡大率で持つ。Retina の Mac(1512×804 の窓)では机だけでタイル約 135 枚(350MB 前後)になり、Chrome のタイル用メモリの上限(約 625MB)を超えた。超えた分のタイルは描かれずに透明のまま出るので、パーツ・字幕・操作部が1コマごとに消えたり現れたりして、画面全体が点滅する(止めていても続く。カメラが引く場面や、画風のフィルタ付きのパーツを描き直す場面で出やすい。解像度が1倍の画面では上限に届かず、出ない)。木目を無地にしても変わらない。canvas の絵は層がその大きさ(3000×2300、約 28MB)で済む。`?table=0` で差し替えをやめ、`?table=1` などで細かさを変えられる。canvas に描くときは、背景の中の模様(`fx.noise` の SVG)を先に元の大きさのまま画像にし、机の絵は復号(`decode()`)を待ってから描く。Safari は、SVG フィルタの模様を 3000px を超えて引き伸ばして表示すると模様を描かずに捨て(CSS の背景のままだと、6000px に引き伸ばす大理石の石目が出ない)、復号を待たずに canvas へ描くと、中に埋めた画像を飛ばして描く。**大きな板を 3D の中に足すときは同じことが起きる**ので、絵を canvas か画像にするか、板を小さくする。調べ方: Chrome のトレース(cc)で `TileManager::AssignGpuMemoryToTiles` の `had_enough_memory_to_schedule_tiles_needed_now` が false、`AppendQuads checkerboard` が出ていれば、これ。
- **絵の中の動き(`anim`)は毎秒 15 回に間引き、時刻が変わらないコマでは呼ばない。** `anim` は SVG の属性を書き換えるので、呼ぶたびにそのパーツの絵が描き直される(同じ値を書いても描き直される)。画風のフィルタが付いた大きなパーツ(家の煙、伸びる木)を毎コマ描き直すと、Retina の Mac の Chrome で毎秒 50 コマ前後まで落ち、止めている間も描き直しが続いていた。板の移動・回転・不透明度は絵を描き直さないので、毎コマ動かしている。`?t=` の静止画モード(検査・動画化)では間引かない。`?afps=<回数>` で変えられ、`?afps=0` で間引かない。
- **ページの下に、表紙の板・束・背を別の面として置かない。紙面のまわりに見える板と束の縁は、ページ自身の面の中に描く(`.ground` の中の `.rim`)。** `.ground` は面ごとの平らな入れ物で、中は書いた順に重なる(縁 → 紙面 → 影)。同じ面の中なので、ブラウザが前後を比べる相手にならない。縁は、山の一番上で寝ているページと、表紙と一緒に動いているページ(開くときの表紙の裏、最後にとじるときの束の一番上)にだけ見せる。ここに至るまでに Safari で起きたこと: (1) 板・束・紙面を 0.6〜0.8px ずつ離した別々の面にすると、板が束の一部の手前に出て、束の縁が途中で切れたり、ちらついたりした。(2) 立っているパーツの面(の延長)でページが帯状に切り分けられ、その帯の前後を下の束や板と取り違えて、束の縞がページを横切る帯になって見えた(左ページの家と右ページのめんどりのように、離れた2枚がそろったときだけ出る)。(3) すき間を 4px、8px に広げても直らず、8px では左ページまで巻き込んで悪化した(近すぎることが原因ではない)。(4) 板と束を平らな入れ物(幅と高さを持つ `div`)にまとめてページの下に置くと、前後は安定したが、画面に出す段階で手前のパーツ(海藻、亀と太郎、サンゴ)が抜けたり点滅したりした。影は残り、スクリーンショットや画面録画には正しく写るので、目で見るしかない。束を板の子にしても、抜け方が変わるだけだった。`.ground` には `isolation: isolate` を付ける(ないと、Safari は中の影を入れ物の外の層として扱い、影が紙面の下に回って消える)。裏面を隠す指定(`backface-visibility`)は `.ground` に付け、中の `.paper` には付けない(付けると Safari で左ページが消える)。
- **カメラに背を向けているページの面は、立体から外す(`display: none`)。** めくり中のページには表と裏の面があり、背を向けた側は `backface-visibility` で描かれない。ところが Safari は、描かない面も前後判定には入れる。めくり始め(と終わり)は、その面がほぼ水平のまま、となりのページのパーツの足元を数 px の高さで横切るので、判定が狂い、手前のパーツ(家・看板)が奥のパーツ(丘)の後ろに回って見える。めくり始めの 0.2〜0.4 秒だけ起き、`?zoom=0` では起きない。表は開き角 156°まで(背で折れたパネルが付いているので `FOLD_SHOW` に合わせる)、裏は 80°から立体に入れ、90°前後だけ両方を残している。
- **めくり中のページは下のページから 3px 浮かせる(紙面を葉から離した 1.4px の2倍より大きく)。** めくり始めの数コマは角度がほぼ 0 で、めくるページと次のページがほぼ同じ高さに重なる。すき間が 0.02〜0.1px しかないと前後が入れ替わり、次のページが一瞬見える(本の後ろのページほどすき間が小さく、起きやすい)。
- **見開きごとの背景は全部を重ねておいて不透明度で切り替える。** 見えていない背景は `display: none` にして、動きの計算もしない。めくりの間だけ2枚が同時に動く。
- **動く背景は 3D の外に置く。** 本の後ろの景色(`scene`)は机の面のような 3D の板ではなく、画面いっぱいの SVG を1枚敷いてぼかしている。3D の中で大きな板を毎フレーム描き直すと重く、ぼかしも掛けにくい。カメラが動いても景色は動かない(本だけが動く)。
- **構造物の床は壁から位置を計算して置く。** `terrace()` の床(屋根・テラス)は壁の子要素にせず、ページに直接置いて毎フレーム「壁の上端の線」に合わせている。壁は背で折れて左右に分かれ、開閉で倒れるので、床はページと平行のまま、壁の傾きと折り角から出した位置へ動かす(折れた壁に沿わせるため、床は平行四辺形にゆがめてある)。
- **ページの下へ沈めたパーツは、根元の線で切って隠す。** 負の `lift` や `sink` で沈めた板は、開ききっていればページに隠れるが、めくり途中は板が傾いているので、沈めた分がページの上を手前へ滑り出て見えてしまう(沈んでいるはずの物が一瞬現れる)。エンジンが `clip-path` で根元より下を切っている。
- **画風のフィルタがかかる範囲は「絵の箱」に固定する。** フィルタの範囲は絵の外形から決まるので、そのままだと腕を振るなどの動きで範囲が毎フレーム変わる。ます目を敷きつめる画風(ドット絵、ポップアートの網点)は範囲の左上にます目の元を置くため、範囲がずれるとパーツが丸ごと消えたり現れたりする。エンジンが、絵の箱と同じ大きさの透明な四角を絵に足して範囲を固定している。
- **立つ板をページ面より下にはみ出させない。** 切り分けたパーツの板が根元より下に数pxでも出ると、板がページと交差し、板の下半分がページや机の裏に回って消える(カメラの位置によって出たり出なかったりする)。
- **重なったページは一番上の1枚だけ描く。** 左右の山のページを全部描くと高さの差で背景の継ぎ目に段差ができ、同一平面に置くと描画順が不定になる。めくっている最中のページだけわずかに浮かせている。
- **パーツは開き角に連動して立ち上がる。** 見開きの開き角 92°→178° の間に 0→1。パーツは左右それぞれのページに取り付けてあり、めくられるページと一緒に動いて、たたまれる。
- **たたむとページの外へ出る板は、たたまれるにつれて薄くして消す(エンジンの `tuckFade`)。** 板は1枚のまま寝るので、背が高い板や高く浮かせた板は、寝たときに本の上や横から突き出て、閉じきった瞬間に急に消える(表紙が開くときと、最後に閉じるときに目立つ)。寝た板の上端(回した板は上の角)がページから 12 を超えて出る板だけ、立ち上がりの最初の3割で濃くなり、たたまれる最後の3割で薄くなる。くの字に折ったパネルは開き角 108°→28° の間で薄くなる。ページの中に収まる板は、そのまま寝る。作品側で書くことはない。
- **非表示の初期状態。** 一度も開いていない見開きのパーツも初回描画で必ず隠す(時刻を飛び越えて描いても残骸が出ないように)。
- **3Dの親要素に `overflow` `opacity` `filter` を付けない。** 付けた要素で立体が平らに潰れる。これらを付けてよいのは末端のパーツと紙面だけ。
- **背景画像のデータURL内の `'` は `%27` にする。** そのままだと `url('...')` が途中で切れて机や紙の質感が消える。
- **`Tobidas` は `const` なので `window.Tobidas` では取れない。** 外部ツールからは `typeof Tobidas !== 'undefined'` で確かめる。
