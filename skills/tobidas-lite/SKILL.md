# tobidas-lite — 飛び出す絵本を作る

題材を聞き取り、同梱のエンジンとテーマの上に「その作品だけの絵と場面定義」を書いて、ブラウザで開けるHTML一式を作る。

## 何が固定で、何を作るのか

| 層 | スキル内の場所 | 作品フォルダでの場所 | 扱い |
|---|---|---|---|
| エンジン(本の機構・時間軸・操作・再生ボタン・音源) | `assets/template/engine/` | `engine/` | 全テーマ共通。**そのままコピー。不具合の修正以外では編集しない** |
| テーマ(画風・机・曲集・効果音・絵の部品・作り方の資料) | `themes/<テーマ>/` | `theme/` | テーマ単位で差し替える。**そのままコピー。不具合の修正以外では編集しない** |
| その作品だけの絵 | — | `book/art.js` | 書く |
| 作品定義(見開き・パーツ配置・動き・字幕・カメラ・音) | — | `book/book.js` | 書く |

エンジンを固定するのは、ページめくりと立ち上がりの3D表現にはブラウザ依存の落とし穴が多く、それらを解決済みの状態で毎回使い回すため。機構に手を入れたくなったら、まず `references/pitfalls.md` を読み、作品定義側で表現できないかを考える。それでも不具合だと分かったときの扱いは、下の「制作中に見つけた不具合」に従う。

テーマは「どんな見た目と音の作品にするか」をまとめた一式で、今あるのは `storybook`(童話の絵本)。テーマの中には確認済みの内蔵の選択肢(画風・机や動く背景・曲集)があり、机や動く背景と曲集は「内蔵から選ぶ」か「この作品のために書き下ろす」かを聞き取りでユーザーが決める。画風は内蔵から選び、書き下ろすのはユーザーが自分から頼んだときだけにする。**書き下ろしはユーザーが選んだ項目だけ。選ばれなかった項目は必ず内蔵を使い、勝手に書き下ろさない**(内蔵は誰が作っても同じ結果になる。書き下ろしは出来が作り手に左右される)。

## 進め方

### 0. テーマを決める

`themes/` の下にあるフォルダがテーマ。1つしかなければそれを使う。2つ以上あれば、各テーマの `guide.md` の冒頭(向く用途)をもとに、題材に合うものを勧めて選んでもらう。ユーザーが自分のテーマパック(フォルダ)を指定したら、それを使う。1作品に使うテーマは1つ。

決まったら **そのテーマの `guide.md` を読む**。以降の手順で「テーマの資料」と書いてあるものは、`guide.md` が案内するそのテーマのフォルダ内の資料を指す。

### 1. 聞き取り

ユーザーが明示した指定は、下の既定やおすすめより常に優先する。

聞き取りは、ブラウザで開く聞き取りページで行う。ユーザーは見本画像と見本の絵本を見ながら選び、最後に出る「結果」を会話に貼る。

1. 題材(どの物語か。オリジナルならあらすじ)が依頼文になければ、それだけを会話で聞く。
2. 題材をもとに、ページに出す候補とおすすめを JSON に書く(書式は下)。おすすめはテーマの資料の「向く題材」から選び、理由を一言添える。
3. 次のコマンドでページを作る。JSON とページは、どちらもユーザーの作業フォルダに置く。

   ```bash
   node <このスキル>/scripts/setup.mjs <出力先>/<作品名>-setup.html --data <出力先>/<作品名>-setup.json --theme <テーマ名>
   ```

4. コマンドが出力した `file://` の URL をユーザーに伝え、ブラウザで開いて選び、「結果をコピー」で写したテキストを会話に貼るよう頼む。
5. 貼られた結果を読み、手順2へ進む。結果に書かれていないこと、互いに食い違うことだけを会話で確かめる。

```json
{ "ui": "ja",
  "topic": "ももたろう",
  "highlights": ["大きな桃が割れて、ももたろうが飛び出す", "鬼ヶ島で鬼を退治する"],
  "recommend": { "style": [["kirigami", "色紙の工作らしさが昔話に合う"], ["crayon", "素朴な手描きの味が出る"]],
                 "desk": ["meadow", "のどかな里の話に合う"],
                 "set": ["wafu", "日本の昔話に合う"] },
  "fixed": { "length": 8 } }
```

| 項目 | 書くこと |
|---|---|
| `ui` | 会話の言語のコード(`"ja"` `"en"` `"fr"` など)。ページはこの言語で出る。日本語と英語は文言を内蔵している |
| `strings` | `ui` が日本語・英語以外のときだけ書く。画面の文言を会話の言語に訳したもの(下記) |
| `labels` | `ui` が日本語以外のときだけ書く。内蔵の画風・机や背景・曲の表示名を会話の言語で書く。`{ "style": { "kirigami": "Paper cutout", … }, "desk": { … }, "set": { … } }` |
| `topic` | 題材 |
| `highlights` | 見せ場の候補を2つ |
| `recommend.style` | おすすめの画風の第1位と第2位。`[名前, 理由]` |
| `recommend.desk` / `recommend.set` | おすすめの本の後ろと曲を1つずつ。`[名前, 理由]` |
| `fixed` | ユーザーがすでに明示した項目だけ書く(`lang` `length` `highlight` `style` `desk` `set`)。書いた項目は選んだ状態で出る |

会話が日本語でも英語でもないときは、ページの文言も会話の言語にする。`node <このスキル>/scripts/setup.mjs --strings` が英語の文言を JSON で出すので、同じ形のまま値だけを訳して `strings` に書く。`{topic}` と `{n}` は差し込みの目印なので、そのまま残す。訳していない項目は英語で出る。内蔵の表示名はテーマが日本語で持っているので、日本語以外の会話では `labels` も書く(書かなかった名前は日本語で出る)。`topic` `highlights` とおすすめの理由も、会話の言語で書く。

ページが聞く項目は次の8つで、文言と選択肢はページに固定してある。

| # | 項目 | 選択肢 |
|---|---|---|
| 1 | 文字の言語 | ページの言語(既定)、英語、ほかの言語(自由記入) |
| 2 | 長さ | 短め(見開き4)、標準(見開き6)、たっぷり(見開き8) |
| 3 | 見せ場 | `highlights` の候補、おまかせ、ほかの場面(自由記入) |
| 4 | 画像・音声ファイル | 画像を使う、音声を使う。使うものは、どれを何に使うかを自由記入 |
| 5 | 画風 | 内蔵の全種(見本画像つき) |
| 6 | 本の後ろ | 内蔵の机と動く背景の全種(見本画像つき)、書き下ろす、用意した画像を背景に使う |
| 7 | 曲 | 内蔵の全種、書き下ろす、用意した音声をBGMにする、音なし |
| 8 | そのほかの希望 | 自由記入 |

答えの扱い:

- 作中の言語は、ページの言語(会話の言語)が既定で選ばれていて、ユーザーが英語かほかの言語に変えられる。ページが英語のときは、英語(既定)とほかの言語の2択になる。題材の出どころから言語を決めつけない(外国の童話を日本語で読みたいこともある)。`fixed.lang` を書くのは、ユーザーが言語をはっきり指定しているときだけにする。
- 作中の言語は、作品の中に出てくる文字すべて(表紙の題字、字幕、看板などの絵の中の文字、最後の一言)に使う。
- 見せ場が「おまかせ」なら、こちらで提案する。
- 字幕の文体は聞かない。作中の言語が日本語なら「ひらがな多めの読み聞かせ調」、ほかの言語なら「短い文とやさしい単語の読み聞かせ調」で書く。
- 画風は内蔵から選ぶ。書き下ろしはこちらから持ちかけず、ユーザーが自分から頼んだときだけ行う。
- 用意した画像は、背景だけでなく人物や小物などパーツの絵の代わりにも使う。画像のないパーツと背景は SVG で描き、用意のない音は合成する。何をどこに使うかは構成表に書く。頼まれていない素材は生成しない。書き方は `references/assets.md`。
- 用意した音声をBGMにする作品では、合成のBGMを止める。

**背景(本の後ろ)の扱いは内蔵か書き下ろしかで変わる。** 内蔵の机・動く背景を選んだら、全部の見開きで同じものを使う。**書き下ろしを選んだら、見開きごとにその場面に合う背景を書く**(昼の港 → 夜の甲板 → 夕焼け → 室内、のように場面の時刻・場所に合わせる。同じ場所・時刻が続く見開きは同じ背景でよい)。表紙と結び用に、作品全体を表す背景も1つ決める。構成表に見開きごとの背景を書いて、了承をもらう。

残りは既定値で進め、構成表の中で示して直してもらう: 装丁の色(題材から選ぶ)、カメラ(穏やか。見せ場だけ大きく動かす)、1見開き約7〜8秒、効果音あり。

### 2. 構成表を出して承認をもらう

見開きごとに次を1行ずつ書いた表を見せ、了承を得てから制作に入る。絵を描き始めてからの構成変更は高くつくため。

| # | 場面 | 舞台(地面・奥の景色) | 立ち上がる主なパーツ | 動き・仕掛け | 音(BGMの気分・効果音) | 字幕(2行まで) |
|---|---|---|---|---|---|---|

本の後ろの背景を書き下ろす作品では、表に「本の後ろの背景」の列を足し、見開きごとに書く(例: 晴れた昼の海/星の夜/夕焼け/船の中)。表紙と結びの背景も1行で示す。

- 見せ場は全体で1〜2か所に絞り、ほかの見開きは「小さな動き3つ程度」に抑える。全部を派手にすると見せ場が埋もれる。
- 仕掛けはテーマの資料にある型から選ぶと確実。見せ場に建物(城・塔・神殿・舞台など)があるなら、板1枚ではなく段々の構造物(`terrace()`)で組むと決め、構成表の「立ち上がる主なパーツ」に段の並びを書く。
- 作中の言語、表紙の題字・色、最後の一言(日本語なら「おしまい」など)、聞き取りで決まった項目(内蔵の名前、または書き下ろしの方針)も合わせて示す。
- storybookで表紙の音を示すときは、「エンジンの短いメロディー。BGMは最初の見開きから」と記す。ユーザーが表紙へのBGM追加を明示した場合は、その内容を構成表に入れる。

### 3. 作品フォルダを作る

制作を始める前に、手順1で未確定の項目をユーザーと相談し、手順2で仕様と構成表を提示して、提示した内容全体への了承を得る。個別の質問への回答はその項目の確定として扱う。「おまかせ」と指定された項目は推奨案を構成表に入れる。修正の希望があれば、更新した構成表を提示して了承を得る。

仕様と構成表への了承を受けてから、次のコマンドで作品フォルダを作り、作画に入る。了承を待つ間は、資料の確認や構成案の検討を進められる。

```bash
node <このスキル>/scripts/new-book.mjs <出力先>/<作品名> --theme <テーマ名>
```

ひな形(`index.html` と `engine/`)、テーマ(`theme/`)、そのテーマの書き出し用の `book/` がコピーされ、素材置き場の `assets/`(空)ができる。画像・音声ファイルを使う作品は、素材を `assets/` に置き、音声は `node <このスキル>/scripts/embed-audio.mjs <作品フォルダ>` で埋め込む(`references/assets.md`)。出力先はユーザーの作業フォルダ。`index.html` は `<title>` と `lang` だけ直す(`lang` は聞き取りで決めた作中の言語)。`--theme` にはテーマパックのフォルダのパスも書ける。

### 4. 絵と場面を書く

読む順: `references/book-api.md`(定義の書き方・座標系。全テーマ共通)→ テーマの資料(`guide.md` が示す順)。

- 本の後ろの背景を書き下ろす作品は、見開きごとの `scene` と、表紙・結び用の `theme.desk` の `scene` を書く(`references/book-api.md` の「見開き」、`references/theme-format.md` の「動く背景」)。似た景色は色や要素を引数にした関数1つから作り分けると、書く量が減り、見た目もそろう。めくりの途中(背景が入れ替わるところ)も撮って確かめる。
- 最初に、聞き取りで決まった項目を `Tobidas.book({...})` に書く(作中の言語は `lang`。storybook なら加えて `theme: { style, desk }` と `sound: { set }`)。書き出し用の `book/` に入っている日本語の仮の文字(表紙の題字や「おしまい」など)は、作中の言語に合わせて全部書き換える。**作中の言語が日本語以外なら、`theme.font` に欧文のフォント(例: `'"Noto Serif","DejaVu Serif",Georgia,serif'`)を指定し、表紙の題字の `font-family` も同じにする。** 既定のフォント `FONT` は日本語の明朝体が先に来るので、「…」が行の真ん中の点「···」になるなど、欧文の記号が日本語の字形で出る。書き下ろす項目があれば、ここでテーマの資料の書き方に従って書き、表紙と最初の見開きで見え方を確かめてから先へ進む。
- 先に `book/art.js` に登場人物と題材固有の物を描き、次に `book/book.js` で見開きを1つずつ組む。登場人物は描いたらすぐ最初の見開きに置いて撮り、大きさと顔を確かめてから残りを描く。
- **見開きを1つ書くたびに手順5のチェックを回す。** 全部書いてから確認すると、同じ間違い(大きさ・位置・重なり)を全見開きに複製してしまう。
- 音は見開きごとに `music`(BGMの気分)と `sfx`(効果音の時刻)を書くだけ。仕掛けの時刻は定数にして、動きと効果音の両方で使う。
- **パーツは片ページに収めるか、背の上でくの字に折るかのどちらかにする。** 背(X=0)を少しだけまたぐ置き方は、めくるとき左右に分断されて見える。置く前に左端 `X − 幅/2` と右端 `X + 幅/2` を確かめ、背を越えるなら、片ページに収まるよう X か幅を直すか、`fold` で折る(`references/book-api.md` の「背をまたぐパーツ」)。動かす物は `nosplit: true`。
- 1見開きのパーツは15〜30個が目安。奥(Yが小さい)に背景、手前に人物、いちばん手前に草や茂み、と層を重ねると立体感が出る。

### 5. 撮って確かめる

```bash
cd <このスキル>/scripts && npm install      # 初回だけ
node <このスキル>/scripts/check.mjs <作品フォルダ>              # 全体の一覧
node <このスキル>/scripts/check.mjs <作品フォルダ> --spread 3   # 見開き3を時間方向に細かく
```

`<作品フォルダ>/.check/sheet.jpg` を **必ず画像として開いて見る**。エラーなしでも、絵が崩れているかどうかは見ないと分からない。一覧は縮小されているので、顔や小物など細部は同じフォルダの個別フレーム(`t054.50.jpg` のような名前、1920×1080)を開く。`--times 23.5,33.8` で見たい時刻だけ撮ると一覧も大きくなる。次の点を見る。

- 人物と建物の大きさの釣り合い、顔が判別できるか
- パーツ同士が意図せず重なって主役を隠していないか、ページの外にはみ出していないか
- めくり途中(一覧の各見開きの最初のコマ)で、背の位置で左右に分断されているパーツがないか。動くパーツや浮いたパーツがある見開きは、めくりの前後を `--times` で細かく撮り、ページを突き抜けたり大きく振れたりしていないか
- 背をまたぐ背景が左右でつながっているか。背で「くの字」に折れるので、端のほうで近くの物と前後が入れ替わったり突き抜けたりしていないか
- 背をまたいで切り分けられるパネルは、見開きが開ききった個別フレームを原寸で開き、上端と左右端に意図しない欠けがないことを確認してから完成とする。丘の稜線に並ぶ木や屋根飾りなど、絵の小さな突起も見る。パネルの枠外は切れるため、欠けていたら絵を収める余白を足して撮り直す（`references/book-api.md` の「背をまたぐパーツ」）。
- 字幕が読めるか、本の重要な部分に被っていないか
- 仕掛けの各段階(`--spread N` で確認)が意図どおりか。高く伸びる物はカメラの画面内に収まっているか

スクリプトは音も合成して、名前の間違いと長い無音区間を報告する。背をまたいで切り分けられる板で、絵が箱の上へはみ出して切れる箇所も警告する。スクリプトが出す警告とエラーは全部直す。Chrome が見つからない環境では `CHROME_PATH` を指定するか、ブラウザ操作ツールで `index.html?t=<秒>` を開いて確認する(`?t=` を付けるとその時刻の静止画になる)。

storybookでBGMを変更したら、完成報告前に `sound.extra` などの追加音も含め、表紙の時間帯にBGMが重なっていないことを確認する。表紙への追加を了承済みの場合は、構成表どおりの開始位置を確認する。

### 6. 渡す

- `index.html` をブラウザで開けば動く(サーバー不要)。操作: ホイール=進む/戻る、←→=見開き単位、左下の▶ボタンか Space=音つきの自動再生(どの位置からでも、そこの音から始まる)、M=音のオン/オフ、D=デバッグ表示、左下のプルダウン=画風の切り替え(読み直して同じ位置に戻る。出したくない作品は `theme.stylePicker: false`)。
- 何を確認し、何を確認していないかを正直に伝える。静止画は確認できても、実機での動きの滑らかさは見られていないことが多い。音は合成が通ることしか確かめられず、耳では聞けていないので、そう伝えて聞いてもらう。
- 画像・音声ファイルを使った作品は、`assets/` を含むフォルダごと渡すよう伝える。素材の出どころは作品の `README.md` に書く。
- 動画ファイルと、ナレーション(声)の生成はこのスキルの範囲外(用意された声の音声ファイルを鳴らすことはできる)。後付け用に `tobidas:time` イベント(現在時刻を通知)を用意してある。
- 制作中に不具合を見つけて直した場合は、下の「制作中に見つけた不具合」のとおり、スキルへのフィードバックを必ず提案する(なければ「なし」と書く)。
- 動画が欲しいと言われたら `node scripts/render-video.mjs <作品フォルダ>`(要 ffmpeg。音つきで書き出す)。

## 制作中に見つけた不具合

制作中に、エンジン・テーマ・検証スクリプトの不具合や、この手順書・資料の誤りや不足に気づくことがある。次のように扱う。

1. **作品側はその場で直してよい(ユーザーへの確認は不要)。** 作品フォルダにコピーした `engine/` `theme/` も含む。作品を完成させることを優先する。直す対象は不具合に限り、好みの変更や機能追加はしない。
2. **スキル本体(このスキルのフォルダ)には、制作中は手を入れない。** スキルは他の作品にも使われるので、変更はユーザーが決める。
3. **見つけるたびに控えておく**: 何が起きたか、原因、作品側でどう直したか(どのファイルのどこ)、スキルのどこをどう直せば再発しないか。
4. **完成報告のときに、必ずスキルへのフィードバックを提案する。** 手順6の報告の最後に、控えた内容を1件ずつ下の表にして示し、スキルに反映してよいかを尋ねる。1件もなければ「スキルへのフィードバックはありません」と書く。作品側だけ直して黙って終わらせない(次の作品で同じ不具合に当たるため)。

   | # | 起きたこと | 原因 | 作品側での対応 | スキルへの提案(直す場所と内容) |
   |---|---|---|---|---|

5. **ユーザーが受け入れた提案だけを、スキル本体に反映する。** 件ごとに採否が分かれてよい。反映先は内容に合わせて選ぶ。
   - 機構や音源の不具合 → `assets/template/engine/`(作品側で直したのと同じ修正)
   - テーマの画風・机・曲・効果音・絵の部品の不具合 → `themes/<テーマ>/theme.js` `parts.js`
   - 検証で見落とした問題、機械的に検出できる問題 → `scripts/check.mjs` に検査や警告を足す
   - 全テーマに共通のはまりどころ → `references/pitfalls.md`。そのテーマの描き方・仕掛けの話 → テーマの資料
   - 手順の抜け → この `SKILL.md`(テーマ固有の手順なら `themes/<テーマ>/guide.md`)
6. **反映したら確かめる。** そのテーマの見本(`node scripts/check.mjs themes/<テーマ>/examples/<見本>`)と、新しく作った作品フォルダ(`new-book.mjs` で作って `check.mjs`)を撮り、一覧画像を見て壊れていないことを確認してから、何を反映したかを報告する。エンジンを直したときは全テーマの見本を撮る。過去に作った作品はコピーを持っているので自動では直らないことも伝える。
